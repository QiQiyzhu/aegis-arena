# v2.1 原生音频验证记录

本轮新增七首原创阶段音乐与十七个事件音效。除了记录播放命令，还使用 Unreal AudioMixer 的 Master Submix 导出，确认实际混音有信号、M 静音后无信号、恢复后重新有信号。以下是验证工具迭代，不能当作 AI 策略改进。

第一次编辑器操作探针的 36 条原生规则断言通过，但严格包装器拒绝了新增音乐 Actor 缺少显式 RootComponent 的警告。修复只为第一个音乐组件设置根节点、第二个挂接其下；随后的独立 Windows 包操作检查通过。

第一轮音频探针的静音导出缺失：UE 的静音 Submix 会停止渲染，录音器没有数据。验证启动参数增加 `au.NeverDisableSubmixes=1`，让实际的静音缓冲也经过混音和录音。第二轮成功生成三份 WAV，但三个文件均为零；包装器正确拒绝“正在播放”的假成功。核对本地引擎源码后，定位到离屏窗口默认受 `UnfocusedVolumeMultiplier=0` 影响。仅在探针启动参数覆盖为 1 后，第三轮编辑器及最终独立包都通过。

原始片段为 48 kHz、双声道 PCM16。15 条原生断言还覆盖第一阶段配乐、暂停时低音量配乐、暂停期间 M、恢复战斗、两次正常 R 重开，以及正常菜单 X 退出。声音对象预算为一个音乐 Actor、两个 AudioComponent；瞬间切换允许两个声音交叉淡化。

这些片段证明引擎 Master Submix 的实际输出，未经过物理扬声器或麦克风，也不是主观试听。七首音乐已加载，不等于本探针对七首都进行了完整 PCM 录制。正式演示视频按照真实引擎命令、原音源、双通道复用和淡化离线重混；不将其称为硬件回环录音。两个离屏测试覆盖项不会加入正常试玩启动器，正式游戏仍遵循默认失焦静音行为。

最终包测试另记录设备采样率 44.1 kHz，而引擎使用 48 kHz。UE 的 WASAPI 实现为此启用 AUTOCONVERTPCM；验证器仅接受这一对精确转换提示，同时记录在证据里，其他音频警告仍失败。Master Submix 的导出保持 48 kHz，不将其称为设备端逐样本输出。对应被拒绝的 `audio-package-02` 保留，之后 `audio-package-03` 在新的严格校验下重新运行通过。
