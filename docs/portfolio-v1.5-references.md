# v1.5 系统／综合策划作品集：近期获奖参考

本文保留研究阶段的建议与验收设想；“正在实现”“建议”等措辞表示当时的设计推断。最终实际实现、实测结果和限制以 [交付记录](portfolio-delivery.md) 及随附设计说明为准。

核实日期：2026-09-18。岗位方向已明确为**系统／综合策划**；战斗和关卡用于展示核心循环、资源取舍、阶段目标、成长选择与信息反馈。以下选择三个在 **2025–2026 年获奖的游戏**，不是三个“获奖 Demo”。奖项事实、公开试玩状态和本项目的设计推断分开记录；研究没有替用户声称玩过、通关或累计游玩时长。

## 1. Hades II：让成长选择改变下一次操作

**来源事实。** 官方商店描述了武器与 Boons 的组合、每轮探索中的升级系统，以及永久成长；也说明其表现由手绘环境与实时 3D 角色结合。此处不引用未核实的具体资源恢复数值。[官方商店说明](https://store.steampowered.com/app/1145350/Hades_II/)

**对 Aegis 的设计推断。** 小型 Demo 无需照搬庞大的长期养成。现有 Uplink 已有三阶段目标与三选一升级，优先把“选择前的理由—选择后的行为变化—实际结果”拍清楚。例如 Piercing Rounds 鼓励排线，Rescue Pulse 鼓励靠近队友再释放，Life Link 奖励真实有效输出。只选一种就放弃同次其他选项，这是已有的机会成本。本轮还在实现共享能量的原型，应让“收益来源→选择脉冲或修复→剩余额度与冷却”可见；其运行与平衡结果尚须新版本实测，不预先宣称已经验证。

**可落地的视觉表达。** 采用原创的冷色环境与更亮的角色／交互轮廓，背景纹理弱于危险预警；升级卡使用统一版式，写清一个核心收益、适用情境和本次未选的方向。选中后将同一图标带入 HUD、实际效果和结算页。穿透轨迹、治疗脉冲和生命恢复反馈必须由真实命中／恢复事件触发，不能只播放看似生效的动画。

**验收证据建议，尚非完成声明。** 连续镜头记录“选择卡→下一场实际触发→HUD／生命变化”；卡片数字与运行规则一致，失败触发条件可解释。展示一个完整小循环比罗列十种未实现能力更能说明系统策划工作。

## 2. Blue Prince：一个清晰远期目标，几次有代价的当下决定

**来源事实。** 官方页面将 Room 46 作为探索目标；玩家决定门后出现的房间，房间选择和找到的工具影响进展；布局每天重置，部分永久升级可保留。[官方商店说明](https://store.steampowered.com/app/1569580/Blue_Prince/) 这是一款第一人称解谜／策略游戏，引用的是目标与选择结构，不是将其画面或玩法误称为俯视角战斗。

**对 Aegis 的设计推断。** 在同一小地图中，把“启动中继→顺序传输→清敌后撤离”做成可一眼辨认的阶段链。让玩家始终知道当前完成条件、下一个目标和剩余资源；生命、脉冲冷却、共享时限、升级机会以及正在实现的共享能量共同服务于短 Demo 的取舍。先展示“留在圈内加速／离圈处理威胁”的选择，再展示下一阶段如何改变任务要求，不需要新增程序化房间生成器。

**可落地的视觉表达。** 每个阶段有明确地标、地面编号和进度段；用几何形状、短文字和颜色共同区分未激活、充能、争夺、完成。争夺时停止填充并显示阻止原因；最后阶段明确“先清敌，后撤离”。场景灯光与环境装置随着真实阶段完成变化，让目标进展同时发生在世界与 HUD 中。不能只给三个相同圈换颜色，却声称关卡结构已改变。

**验收证据建议。** 视频各保留一次“玩家做了什么→资源或目标状态怎样变化”；文档附一张状态图，标出进入／退出条件、冻结条件和失败条件。若沿用现有规则，就准确写为“表现重构”，不要写成全新系统。

## 3. Tactical Breach Wizards：展示决策因果，控制 Demo 信息量

**来源事实。** 官方商店说明角色拥有不同能力、可通过升级改变组合，并可回退尝试。开发商还公开解释：早期 The Lost Demo 将时间跳跃、未来内容与难度选择挤入两个关卡，新玩家难以理解，因此最终采用更简单的公开试玩。[官方商店与开发者说明](https://store.steampowered.com/app/1043810/Tactical_Breach_Wizards/)

**对 Aegis 的设计推断。** 借鉴的是“让尝试与后果容易理解”和“先教一个问题”，不把实时动作原型改成回合制，也不宣称已经实现撤销。公开演示优先显示玩家需要的目标、危险、冷却、队友命令反馈；BT／EQS 分数放在独立解释片段。一次只讲一个升级或决策，先让观众看见效果，再补充为什么这样设计。

**可落地的视觉表达。** 敌人预警使用清楚的方向与结束节拍；命中、格挡／被掩体挡住、治疗、目标争夺分别使用不同反馈。只展示当前合法可见的信息，不能为“易读”而标出隐藏敌人的实时位置。设计讲解可用“请求→采用的行为→实际结果”的三栏，而不是满屏原始调试数值。

**验收证据建议。** 选一个确实存在的失败或误读案例，说明问题、改动和核对方法；同时展示一个限制。现有 Decision Lab 的“waiting 不等于全部静止”就是可用的解释案例，但 v1.4 的 36 局结果只能标注为历史机制评估，不能冒充 v1.5 新画面或新玩法已验收。

## 本轮建议优先级与呈现范围

| 优先级 | 可实施内容 | 策划问题与所需证据 |
|---|---|---|
| P0 | 重做阶段目标条、世界地标和争夺／撤离状态 | 玩家能否理解当前目标？用状态图与对应实机帧说明每个转换。 |
| P0 | 把已有三选一升级做成“收益—适用情境—机会成本”卡片 | 选择是否影响下一阶段操作？录制至少一次真实效果，不只拍选择界面。 |
| P0 | 统一角色／敌人／目标的形状、明度、材质与反馈层级 | 画面升级是否改善信息表达？同分辨率同场景前后对照，保留危险与目标的可见性。 |
| P1 | 战斗反馈连接真实伤害、治疗、冷却与目标事件 | 看起来有效是否真的有效？记录触发、数值或状态变化，区分预警和已命中。 |
| P1 | 一段完整循环＋一个迭代反例＋有限结算数据 | 作品是否证明设计过程？现有证据按版本引用，新版本验证完成后再填结果。 |

以上是适配 Aegis 的原创设计建议，不是奖项评委给出的统一获奖公式。美术升级以真实游戏画面呈现；不复制参考游戏资产，也不把剪辑、概念图或 AI 生成图当作新实机。

交付应为可直接附件上传的 **MP4（≤300 MB）＋设计说明 PDF**，清楚列出本次实际实现、使用素材来源、个人贡献与工具／协作边界。建议视频控制在约 2–3 分钟，关键因果片段保留连续镜头，其余剪辑明确分段；文件最终大小和可播放性以实际导出验收为准。具体一页证据提纲见 [portfolio-v1.5-outline.md](portfolio-v1.5-outline.md)。
