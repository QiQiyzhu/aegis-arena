# Portfolio v1.5：系统循环与实现边界

审计日期：2026-09-18。目标岗位是系统 / 综合策划。主体验沿用 Uplink 的三阶段任务，用一个新增的共享能源系统形成可以说明原因、观察结果的取舍。Decision Lab 保留为实验方法附录；Copilot 保留在旧 v1.3 入口，Portfolio 模式不创建模型规划器。旧版本证据不重写，也不把 AI 实验胜率移用于这套新战斗参数。

本文记录代码核对、已实现规则与验收要求。资源纯模型 32 项检查通过；随后主任务的 Editor 原生输入 / 交易夹具通过 25 项检查。独立包、完整游玩和最终录制仍各自验收，不能用纯模型或夹具测试代替。

## 可直接复用的主循环

**阅读目标 → 选择站位与队友命令 → 战斗 / 占点 → 获得能源 → 在脉冲与修复间取舍 → 完成阶段 → 选升级 → 面对下一阶段。**

| 阶段 | 现有规则 | 玩家要做的决定 | 应看见的反馈 |
|---|---|---|---|
| Secure | 一个中继点，基础累计 4 秒；仍需清掉本阶段敌人 | 自己守点还是让队友 Rally 占点；是否花能源排除争夺 | 点位、争夺状态、进度、能源支出 |
| Transfer | 两个依次启用的中继点，各累计 4 秒；前点完成后再观察新点占用 | 保留资源走向第二点，或现在使用技能降低风险 | 点位切换、1/2 与 2/2、队友位置与命令 |
| Extract | 清掉敌人后占点累计 3 秒；玩家必须亲自入圈 | 先消灭威胁，再带队进入撤离点 | 精英与残敌状态、撤离条件、完成结算 |

占点半径是 260 cm。两名存活友方共同占点时速率为 1.5 倍；敌人入圈时进度停住，既有模型不会倒扣进度。Rally 有正常导航约束，不能宣称下令就保证到点。敌人清完但任务未完成时，流程仍保持 Active；占点完成但仍有敌人时也不能跳过战斗。

`Trial` 的上限是 180 个游戏秒，前两次阶段间隔各为 5 个游戏秒；升级、菜单和指令面板暂停不消耗这个游戏时钟。3–5 分钟是含讲解 / 升级选择的演示目标，不是当前代码保证的每局时长。旧版合成驾驶曾自然失败，不能因此称现有难度已适合所有首次试玩者。

## 一项新增核心系统：共享能源

| 规则 | v1.5 实现 |
|---|---|
| 初始 / 上限 | 60 / 100；没有等待回能 |
| 击杀收入 | 每个被本队真实击杀的敌人 +12；身份按本局分配并去重 |
| 阶段收入 | 每个已完成阶段 +25，阶段 1–3 各一次 |
| Q 脉冲 | 花 35；沿用真实伤害、击退、0.45 秒打断和 6 秒冷却 |
| E 修复 | 花 40，8 秒冷却；自身最多 +30 HP，500 cm 内且几何无遮挡的存活同伴最多 +20 HP |
| 无效修复 | 没有合法缺血对象时不花费、不进入冷却；不复活角色 |
| 状态限制 | 简报、暂停、菜单、升级、终局和玩家死亡时不接受交易 |
| 重开 | 新玩家 pawn 触发账本、收益身份、冷却、统计、输入和日志会话重置 |

初始 60 能源不能连续支付一次 Q 和一次 E。先 Q 后余额 25，先 E 后余额 20，都需要继续推进取得补给。这是开场可见的机会成本。上限溢出单列记录，玩家可以看出囤积的代价。花费失败应显示准确原因，而不是只显示按钮失效。

能源归零不会让基础战斗失效：移动、普通射击、闪避与手动队友指令仍可用。不会为了继续关卡而强制等待回能或必须请求云端模型。

三选一成长继续使用穿透弹、救援脉冲、生命链接。需要承认现有免费支援、阶段恢复、生命链接和救援脉冲也会治疗；E 的统计只记录 E 实际回复，不能把其他治疗算作新系统贡献。救援脉冲把 Q 的控场与治疗合在一次开支中，可能降低 E 的吸引力，这属于后续平衡观察点，不在没有数据时暗改旧机制。

Portfolio 的初始化预设是玩家最大生命 140、普通射击伤害 18 / 冷却 0.28 秒，同伴最大生命 120。只在新局简报期设置，未改变敌方战斗规则，也不注入战斗中的补血。该预设用于可玩切片，不能与 v1.4 冻结比较实验直接合并计算提升。

## 最小接线与读取顺序

| 代码位置 | 可复用职责 / 本轮边界 |
|---|---|
| `core/include/aegis/trial.hpp` | 三阶段生命周期、死亡 / 超时优先、5 秒阶段间隔 |
| `core/include/aegis/operation.hpp` | 占点、争夺、双人加速、逐个中继点和撤离门槛 |
| `AegisLab.cpp::StartInteractive / DeployTrial / SpawnTrialWave` | 正常玩家与同伴初始化、进入任务、真实敌人和角色分工 |
| `AegisLab.cpp::UpdateObjective / UpdateInteractive / ChooseUpgrade` | 从世界占用得到任务推进、阶段暂停和成长选择 |
| `AegisAIController.cpp::SetTacticalContext / SetCompanionCommand / ExecuteTacticalTrial` | 联队位置、Guard / Focus / Rally、敌人站位与可读射击预警；不新增一套 AI |
| `AegisCharacter.cpp::TryPulse / UAegisCombatComponent::FireAt` | 正常输入 / 冷却 / 物理命中链；Q 的支付放在原合法性检查之后、效果之前 |
| `core/include/aegis/portfolio.hpp` | 独立能源账本；只接受世界已验证的交易资格和唯一身份 |
| `AegisPortfolio.cpp::Initialize / SynchronizePlayer / ObserveProgress` | 只在 `-AegisPortfolio` 启用；按 pawn 重开；阶段完成后、升级暂停前精确收取奖励 |
| `AegisPortfolio.cpp::OnDamage / TryRepair / FinishSession` | 监听真实伤害死亡、执行真实治疗、输出本局收支与完成 / 中断结果 |

新 actor 的 `Find(UWorld*)`、`GetEnergy()`、`GetRepairCooldown()`、`GetFeedback()`、`GetFeedbackAge()` 和 `GetStatistics()` 供 HUD 只读显示。E 使用 actor 自己的 InputComponent；只创建在 Portfolio 模式，避免污染旧入口。相机采用独立试玩预设，向场景中心作有界偏移，不改变镜头朝向来追赶目标。

Portfolio 监听世界伤害是系统结算权限，不是 AI 观测权限；这些数据没有送给队友感知或模型。击杀去重不使用会被 Unreal GC 重用的裸对象索引，而是包含对象 serial 的弱引用映射到本局递增 ID。

原 Copilot 已绑定 `AAegisScenarioRunner` 的当前 pawn、阶段、波次和 relay，可以复用其取消与陈旧响应守卫。模型只能给 guard / capture_relay / focus_visible / regroup 等受约束计划，不能给任意坐标；Focus 仍要求同伴当前 Sight。当前 `Startup` 仅在非 Portfolio 的原入口创建 `SquadPlanner`，因此 Portfolio 没有 Tab 云指令流程，使用 Z/X/C 手动命令，在无网络、无 API Key 时完整可玩。若另录旧入口的真实云端演示，应注明版本、请求来源与延迟，不能用本地 fixture 冒充模型。

Decision Lab 的 `Initialize / StartEncounter / Sample / Finish` 继续运行独立的经典 Utility → BT → EQS 路径；Uplink 的 tactical 分支在 `ExecuteAction` 中转入 `ExecuteTacticalTrial`。两者不是同一策略的两种 UI。作品讲解可以引用 Decision Lab 的失败复现与负结果，但不能把新资源玩法称为 Utility / EQS 优化或 RL 训练结果。

## 验证清单与设计指标

| 层级 | 必须看见的事实 | 本轮可据此下的结论 |
|---|---|---|
| 纯账本 | 32 项检查：重复身份 / 阶段、超支、上限、无资格、无接收者、非法时间、冷却、重置、混合事务守恒 | 账本规则通过；不证明按键、治疗、关卡或手感 |
| 原生输入 | 正常 Q / E 支付；低能源拒绝；E 无缺血对象拒绝；缺血时真实 HP 增量；暂停时余额和冷却不变 | 原生接线与反馈吻合规则 |
| 生命周期 | 同一击杀 / 阶段只入账一次；新波身份不碰撞；死亡后不获利；重开新会话；退出与重开不写成功标记 | 有限经济不会被重复回调、暂停或重启破坏 |
| 任务 | 三阶段、两个升级、新 relay、争夺、清敌与最终本人入圈；保留失败结局 | 展示完整系统循环，不能只剪出开场击杀 |
| 资源取舍 | 至少一次实际 Q、一次实际 E、一次能源不足或可见余额抉择；E 实际回复 / 40、Q 实际控场结果分别记录 | 玩家能读懂花费与收益；不能仅凭支付成功称技能有效 |
| 真人观察 | 首次理解目标的时间、错按 / 无效修复次数、首次死亡原因、选择理由、是否理解下阶段变化 | 用户理解度与节奏反馈；合成驾驶不能替代此层 |

建议先看几个可解释指标：每阶段时长、争夺累计时间、能源总入账 / 支出 / 溢出、Q/E 次数、E 自身 / 同伴实际回复、同伴存活、升级选择及任务成败。胜率只适合在样本、难度、操作者和参数都明确时报告；当前单次视频不承担平衡证明。

日志在 `-AegisPortfolioOutput=` 目录内生成每局 GUID 命名的 JSONL 与 JSON。`energyEarned` 是实际进入余额的收入，`energyOverflow` 是丢失的上限溢出；守恒式是 `60 + earned - spent = final`。治疗字段仅为 E，伤害字段是实际 HP 扣除。中途重开为 `restarted`，退出为 `aborted`；只有真实 Won / Lost 且日志完整写入后，输出该局唯一 `AEGIS_PORTFOLIO_COMPLETE` 标记。这个标记证明终局记录完成，不代表胜利。

### preview-02 的实际结果与限制

开发预览 `D:/AegisWork/Reports/portfolio-v1.5-20260918/preview-02` 使用脚本输入、真实 AI / 伤害，记录为 Won；任务经过 90.5 个游戏秒，会话含简报为 94.5 个游戏秒，捕获视频时间轴为 105.6 秒。这三个字段有不同起止点，不能互换，也不是 3–5 分钟真人试玩结果。

该局 12 次击杀与 3 个阶段提供名义收益 `12×12 + 3×25 = 219`；实际入账 195、溢出 24，5 次 Q 花费 175，结余 `60 + 195 - 175 = 80`。逐笔记录与结算相符。24 点溢出发生在阶段 2：当时余额 99，+25 仅有 1 点进入余额。阶段 1 / 2 选择了救援脉冲和生命链接。

该局 **0 次 E、E 实际回复 0**，玩家承伤 20、同伴承伤 28。它证明阶段和 Q 收支循环发生，尚不能证明玩家在自然战斗中体验到了 Q/E 两难，也不能称 E 已在这段视频中发挥作用。独立冻结 AI、显式注入伤害的 25 项原生 probe 用来验证 E 接线，必须与自然演示分列。后续预览或最终录制即使不同，也保留这次结果，不事后替换它的统计。

## 3–5 分钟演示安排

建议先用约 20 秒说明“推进目标会补给，但控场和修复共用能源”，随后连续展示一次战斗中的选择、占点 / 队友命令、阶段升级和下一阶段变化，最后用真实结算解释资源结果。技术附录可用约 20–30 秒点出感知权限和 Decision Lab 的独立比较，主画面以可玩任务为主。

录制必须保留失败风险与真实余额变化，剪辑需标明跳转，不使用隐藏治疗或篡改 AI 状态制造顺利通关。若演示局不足 3 分钟，剩余时间用机制解释和真实日志复盘，不通过等待凑时长。1080p / 30fps、视频约 6 Mbps、音频约 128 kbps 的 5 分钟估算约 230 MB，留出封装与码率浮动余量后再检查实际文件低于 300 MB；这是编码预算，不是已生成视频的大小。
